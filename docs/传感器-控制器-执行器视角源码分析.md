## 1. 系统架构概览

### 1.1 三层架构

```
┌─────────────────────────────────────────────────────────┐
│                    传感器层 (Input)                      │
│  曲轴位置、温度、压力、电压、节气门位置、氧传感器等        │
└────────────────────┬──────────────────────────────────┘
                      │ 原始数据/ADC值
                      ↓
┌─────────────────────────────────────────────────────────┐
│                   控制器层 (Processing)                   │
│  数据转换、查找表、计算算法、修正应用                      │
└────────────────────┬──────────────────────────────────┘
                      │ 控制输出（脉宽、提前角）
                      ↓
┌─────────────────────────────────────────────────────────┐
│                   执行器层 (Output)                       │
│  喷油器、点火线圈、分级喷油器、其他执行器                  │
└─────────────────────────────────────────────────────────┘
```

### 1.2 数据流向

```
传感器硬件 → ADC硬件 → 传感器处理代码 → 控制器计算代码 → 执行器控制代码 → 执行器硬件
```

```c
void generateCoreVars(){
    // TPS ADC值限制和偏移
    unsigned short unboundedTPSADC = ADCArrays->TPS;
    if(unboundedTPSADC > fixedConfigs2.sensorRanges.TPSMaximumADC){
        boundedTPSADC = TPSADCRange;
    }else if(unboundedTPSADC > fixedConfigs2.sensorRanges.TPSMinimumADC){
        boundedTPSADC = unboundedTPSADC - fixedConfigs2.sensorRanges.TPSMinimumADC;
    }else{
        boundedTPSADC = 0;
    }
    
    // TPS转换为百分比
    unsigned short localTPS;
    if(TPSADCRange != 0){
        // 线性转换：百分比 = (有界ADC值 × 100%) / ADC范围
        localTPS = ((unsigned long)boundedTPSADC * oneHundredPercent) / TPSADCRange;
    }
    CoreVars->TPS = localTPS;  // 存储为百分比 × 100（例如5000表示50.00%）
}
```

**功能说明**：
- **偏移校准**：TPS传感器可能有死区，需要减去最小值
- **百分比转换**：转换为0-100%的百分比值
- **单位**：存储为百分比 × 100

### 2.2 传感器数据采集时机

**同步采样**（`Simple.c:131`）：
```c
void PrimaryRPMISR(){
    // 在特定的曲轴位置采样所有ADC通道
    // 确保所有传感器数据来自同一时刻
    sampleEachADC(ADCArraysRecord);
    *mathSampleTimeStampRecord = TCNT;  // 记录采样时间戳
```

**为什么同步采样**：
- 消除发动机循环相关的噪声
- 确保所有传感器数据来自同一曲轴角度
- 提高计算精度

**强制采样**（`main.c:86`）：
```c
if(coreStatusA & FORCE_READING){
    // 超时情况下强制采样
    sampleEachADC(ADCArraysRecord);
    resetToNonRunningState();
    coreStatusA |= CALC_FUEL_IGN;
}
```

**为什么需要强制采样**：
- 发动机停止时，没有位置信号触发采样
- 超时保护，防止传感器故障导致系统停止

### 3.4 燃油计算（控制算法）

**代码文件**：
- **`fuelAndIgnitionCalcs.c`** - `calculateFuelAndIgnition()`

**功能**：根据传感器数据和查找表计算燃油脉宽

**执行流程**（`fuelAndIgnitionCalcs.c:64`，注释代码）：
```c
void calculateFuelAndIgnition(){
    // 步骤1：计算空气流量
    if(TRUE /* SpeedDensity方法 */){
        // 空气流量 = (MAP × VE) / 100%
        DerivedVars->AirFlow = ((unsigned long)CoreVars->MAP * DerivedVars->VEMain) / oneHundredPercentVE;
    }else if(FALSE /* AlphaN方法 */){
        DerivedVars->AirFlow = DerivedVars->VEMain;
    }else if(FALSE /* MAF方法 */){
        DerivedVars->AirFlow = CoreVars->MAF;
    }
    
    // 步骤2：计算密度和燃油因子
    DerivedVars->densityAndFuel = 
        (((unsigned long)((unsigned long)airInletTemp * DerivedVars->Lambda) / stoichiometricLambda) 
         * fixedConfigs1.engineSettings.densityOfFuelAtSTP) / densityOfFuelTotalDivisor;
    
    // 步骤3：计算基础脉宽（BPW）
    DerivedVars->BasePW = (bootFuelConst * DerivedVars->AirFlow) / DerivedVars->densityAndFuel;
    
    // 步骤4：应用修正
    // 4.1 瞬态燃油修正（TFC）
    DerivedVars->EffectivePW = safeTrim(DerivedVars->BasePW, DerivedVars->TFCTotal);
    
    // 4.2 发动机温度修正（ETE）
    DerivedVars->EffectivePW = safeScale(DerivedVars->EffectivePW, DerivedVars->ETE);
    
    // 步骤5：计算每个气缸的脉宽
    for(channel = 0; channel < INJECTION_CHANNELS; channel++){
        // 5.1 每缸修正（PCFC）
        channelPW = safeScale(DerivedVars->EffectivePW, TablesB.SmallTablesB.perCylinderFuelTrims[channel]);
        
        // 5.2 添加死区时间（IDT）
        injectorMainPulseWidthsMath[channel] = safeAdd(channelPW, DerivedVars->IDT);
    }
}
```

## 8. 数据转换链

### 8.1 传感器数据转换链

**示例：IAT传感器**

```
物理量：30°C
  ↓
传感器硬件：NTC热敏电阻，阻值变化
  ↓
信号调理电路：阻值 → 电压（0-5V）
  ↓
ADC硬件：电压 → ADC值（例如：300）
  ↓
ADC采样（utils.c:209）：
  ADCArraysRecord->IAT = 300
  ↓
数据转换（coreVarsGenerator.c:131）：
  localIAT = IATTransferTable[300]
  = 30315 (30.315K × 100)
  ↓
存储到CoreVars：
  CoreVars->IAT = 30315
  ↓
用于计算：
  generateDerivedVars() 使用 CoreVars->IAT
  calculateFuelAndIgnition() 使用 CoreVars->IAT
```

**转换表的作用**（`IATTransferTable.c`）：
- NTC热敏电阻的阻值与温度呈非线性关系
- 查找表提供快速、准确的转换
- 避免实时计算复杂的数学公式

### 8.2 控制计算链

**示例：燃油脉宽计算**

```
传感器数据（CoreVars）：
  MAP = 10000 (100.00 kPa)
  RPM = 3000
  TPS = 5000 (50.00%)
  IAT = 30315 (30.315K)
  ↓
查找表访问（generateDerivedVars）：
  LoadMain = calculateLoad(MAP, RPM) = 16000
  VEMain = lookupVE(RPM=3000, Load=16000) = 42500 (85%)
  Lambda = lookupLambda(RPM=3000, Load=16000) = 32768 (1.0)
  IDT = lookupIDT(BRV=14400) = 1000
  ETE = lookupETE(CHT=35800) = 32768 (100%)
  ↓
燃油计算（calculateFuelAndIgnition）：
  AirFlow = (MAP × VEMain) / 100% = 42500
  densityAndFuel = (IAT × Lambda) / ... = 30315
  BasePW = (bootFuelConst × AirFlow) / densityAndFuel = 2500
```

## 9. 关键设计模式

### 9.1 传感器层设计模式

**模式1：硬件抽象**
- **实现**：ADC硬件自动采样，代码只需读取结果
- **好处**：简化代码，提高可靠性

**模式2：查找表转换**
- **实现**：使用查找表代替实时计算
- **好处**：快速、准确、避免浮点运算

**模式3：同步采样**
- **实现**：在特定曲轴位置采样所有传感器
- **好处**：数据一致性，消除循环相关噪声

### 9.2 控制器层设计模式

**模式1：分层计算**
- **实现**：核心变量 → 派生变量 → 控制输出
- **好处**：模块化，易于维护和调试

**模式2：查找表驱动**
- **实现**：使用查找表决定控制输出
- **好处**：灵活调校，无需修改代码

**模式3：修正叠加**
- **实现**：基础值 + 各种修正
- **好处**：模块化修正，易于调整

### 9.3 执行器层设计模式

**模式1：硬件定时器控制**
- **实现**：使用定时器输出比较自动控制
- **好处**：精确时序，无需CPU干预

**模式2：事件驱动**
- **实现**：基于曲轴位置事件调度
- **好处**：精确同步，实时响应

**模式3：双缓冲输出**
- **实现**：计算缓冲区和实时缓冲区
- **好处**：数据一致性，无锁设计
