# FreeMS2 系统原理文档

## 1. 系统概述

FreeMS2 是一个开源的汽车发动机管理系统（ECU），设计用于运行在 B&G 和兼容的 MS2 硬件上，使用 MS2Extra 风格的引脚配置。该系统完全从零开始编写，不包含任何来自先前 MegaSquirt 项目的代码。

### 1.1 系统目标

- 提供完整的发动机管理功能（燃油喷射、点火控制）
- 支持实时调参和数据记录
- 通过串口通信进行配置和监控
- 支持多种发动机位置传感器（曲轴位置、凸轮轴位置）

### 1.2 硬件平台

- **微控制器**: Freescale MC9S12C128 / MC9S12XDP512
- **时钟频率**: 16MHz 外部晶振，通过 PLL 倍频至 80MHz（总线频率 40MHz）
- **内存**: Flash 存储配置和表格，RAM 用于运行时数据
- **外设**: 
  - 多通道 ADC（模拟数字转换器）
  - ECT 定时器模块（用于发动机位置捕获和输出比较）
  - SCI 串口通信接口
  - PWM 输出通道

## 2. 系统架构

### 2.1 整体架构

FreeMS2 采用分层架构设计，主要分为以下几个层次：

```
┌─────────────────────────────────────┐
│    应用层 (Application Layer)        │
│  - 主循环 (main.c)                   │
│  - 燃油和点火计算                    │
│  - 核心变量生成                      │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│    服务层 (Service Layer)            │
│  - 通信协议处理 (commsCore.c)        │
│  - 表格查找 (tableLookup.c)          │
│  - Flash 读写 (flashWrite.c)         │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│    驱动层 (Driver Layer)              │
│  - 中断服务例程 (ISRs)               │
│  - 硬件初始化 (init.c)               │
│  - 外设控制                          │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│    硬件层 (Hardware Layer)           │
│  - MC9S12 微控制器                  │
│  - 传感器接口                        │
│  - 执行器接口                        │
└─────────────────────────────────────┘
```

### 2.2 核心组件

#### 2.2.1 主循环 (Main Loop)

主循环位于 `main.c`，是系统的核心调度器。它执行以下主要任务：

1. **ADC 采样触发**: 当需要强制采样时，读取所有 ADC 通道
2. **燃油和点火计算**: 根据传感器数据计算喷油脉宽和点火提前角
3. **通信处理**: 处理来自串口的命令和数据包
4. **数据记录**: 发送异步数据日志（如果配置）

主循环采用事件驱动模式，通过标志位 (`coreStatusA`) 来控制执行流程。

#### 2.2.2 中断服务例程 (ISRs)

系统使用多个中断服务例程来处理实时事件：

- **发动机位置中断** (`PrimaryRPMISR`, `SecondaryRPMISR`): 
  - 捕获曲轴和凸轮轴位置信号
  - 计算发动机转速 (RPM)
  - 触发 ADC 采样
  - 设置计算标志

- **喷油器中断** (`InjectorXISR`):
  - 控制喷油器的开启和关闭
  - 支持主喷油器和分级喷油器

- **通信中断** (`SCI0ISR`):
  - 处理串口数据的接收和发送
  - 实现数据包的解析和组装

- **实时中断** (`RTI`):
  - 提供系统时钟基准
  - 处理超时检测

#### 2.2.3 数据流架构

系统采用双缓冲（Banked）架构来处理输入和输出数据：

**输入数据流**:
```
传感器 → ADC → ADCArrays0/1 (双缓冲) → CoreVars → DerivedVars → 计算
```

**输出数据流**:
```
计算 → injectorMainPulseWidths0/1 (双缓冲) → ISR → 执行器
```

这种设计确保了：
- 计算过程使用稳定的数据快照
- ISR 可以持续更新输入数据而不影响计算
- 输出数据可以在计算完成后原子性地切换

## 3. 核心功能模块

### 3.1 发动机位置解码

系统支持多种发动机位置传感器模式：

#### 3.1.1 Simple 模式
- 简单的每转脉冲信号
- 适用于基本测试和开发

#### 3.1.2 Missing Teeth 模式
- 支持 36-1、60-2 等缺齿模式
- 通过检测缺齿来同步发动机位置
- 实现文件: `MissingTeeth.c`

#### 3.1.3 Nippon Denso 模式
- 支持 24/2 传感器（丰田发动机）
- 提供半顺序喷油和浪费火花点火
- 实现文件: `NipponDenso.c`

#### 3.1.4 Subaru 36-2-2-2 模式
- 支持斯巴鲁特有的 36-2-2-2 模式
- 实现文件: `Subaru-36-2-2-2.c`

#### 3.1.5 Miata NB 模式
- 支持马自达 Miata NB 的传感器配置
- 实现文件: `MiataNB.c`

### 3.2 传感器数据处理

#### 3.2.1 ADC 采样

系统使用多通道 ADC 来读取各种传感器：

- **MAP** (Manifold Absolute Pressure): 进气歧管绝对压力
- **IAT** (Intake Air Temperature): 进气温度
- **CHT** (Cylinder Head Temperature): 缸盖温度
- **TPS** (Throttle Position Sensor): 节气门位置
- **EGO** (Exhaust Gas Oxygen): 氧传感器（Lambda）
- **BRV** (Battery Reference Voltage): 电池电压
- **MAF** (Mass Air Flow): 质量空气流量（可选）

ADC 采样在发动机位置中断中同步进行，确保数据的一致性。

#### 3.2.2 传感器转换

传感器原始 ADC 值通过以下方式转换为物理量：

1. **线性转换**: 使用最小值和范围进行线性映射
   ```c
   value = (ADC * Range) / ADC_DIVISIONS + Minimum
   ```

2. **查找表转换**: 使用预定义的查找表（如 IAT、CHT）
   ```c
   temperature = IATTransferTable[ADC]
   ```

3. **百分比转换**: 对于 TPS 等百分比传感器
   ```c
   percentage = (ADC * MAX) / ADC_RANGE
   ```

### 3.3 燃油计算

燃油计算流程如下：

#### 3.3.1 核心变量生成 (`generateCoreVars`)

从 ADC 原始值生成核心变量：
- 温度值（IAT, CHT, MAT）
- 压力值（MAP, AAP, IAP）
- 位置值（TPS）
- 氧传感器值（EGO, EGO2）
- 转速（RPM）

#### 3.3.2 派生变量生成 (`generateDerivedVars`)

从核心变量计算派生变量：
- **LoadMain**: 主负荷值（基于 MAP 或 TPS）
- **VEMain**: 主容积效率（从 VE 表查找）
- **Lambda**: 目标空燃比（从 Lambda 表查找）
- **AirFlow**: 空气流量计算

#### 3.3.3 燃油脉宽计算 (`calculateFuelAndIgnition`)

计算最终的喷油脉宽：

1. **基础脉宽计算**:
   ```
   BasePW = (FuelConstant * AirFlow) / densityAndFuel
   ```

2. **修正应用**:
   - 瞬态燃油修正 (TFC)
   - 发动机温度修正 (ETE)
   - 每缸燃油修正 (PCFC)
   - 喷油器死区时间 (IDT)

3. **最终脉宽**:
   ```
   FinalPW = BasePW + IDT + Corrections
   ```

### 3.4 点火控制

点火控制包括：

1. **点火提前角计算**: 从点火提前角表查找
2. **闭合角（Dwell）计算**: 根据电压和转速调整
3. **点火调度**: 在正确的曲轴角度触发点火

### 3.5 通信协议

#### 3.5.1 协议结构

系统使用基于数据包的通信协议：

```
[START_BYTE] [HEADER] [PAYLOAD_ID] [LENGTH] [DATA] [CHECKSUM] [STOP_BYTE]
```

- **START_BYTE**: 数据包起始标志
- **HEADER**: 包含标志位（长度字段、序列号等）
- **PAYLOAD_ID**: 数据包类型标识
- **LENGTH**: 数据长度（如果启用）
- **DATA**: 实际数据
- **CHECKSUM**: 校验和
- **STOP_BYTE**: 数据包结束标志

#### 3.5.2 支持的命令

- `requestInterfaceVersion`: 获取接口版本
- `requestFirmwareVersion`: 获取固件版本
- `requestMaxPacketSize`: 获取最大数据包大小
- `requestEchoPacketReturn`: 回显测试
- `updateBlockInRAM`: 更新 RAM 中的数据块
- `updateBlockInFlash`: 更新 Flash 中的数据块
- `retrieveBlockFromRAM`: 从 RAM 读取数据块
- `retrieveBlockFromFlash`: 从 Flash 读取数据块
- `burnBlockFromRamToFlash`: 将 RAM 数据烧录到 Flash

#### 3.5.3 数据记录

系统支持异步数据记录，可以实时发送发动机运行数据。

## 4. 内存管理

### 4.1 内存布局

系统使用分页内存架构：

- **Flash 页面**: 存储配置表和查找表
- **RAM 页面**: 存储运行时数据，支持实时调参
- **固定配置**: 存储在固定 Flash 区域
- **可调配置**: 存储在可调 Flash 区域，可复制到 RAM

### 4.2 数据表格

系统使用多种数据表格：

1. **主表格 (Main Tables)**:
   - VE 表（容积效率表）
   - Lambda 表（空燃比表）
   - 点火提前角表

2. **查找表 (Lookup Tables)**:
   - IAT 转换表
   - CHT 转换表
   - MAF 转换表

3. **小表格 (Small Tables)**:
   - 闭合角表
   - 喷油器死区时间表
   - 发动机温度修正表
   - 每缸燃油修正表

### 4.3 双缓冲机制

系统使用双缓冲来避免数据竞争：

- **输入缓冲**: `ADCArrays0` 和 `ADCArrays1`
- **输出缓冲**: `injectorMainPulseWidths0` 和 `injectorMainPulseWidths1`
- **切换时机**: 在原子操作块中进行切换

## 5. 系统初始化流程

系统启动时的初始化顺序：

1. **PLL 初始化**: 设置系统时钟频率
2. **IO 初始化**: 配置所有 I/O 引脚
3. **分页 RAM 初始化**: 从 Flash 复制表格到 RAM
4. **变量初始化**: 初始化运行时变量
5. **Flash 初始化**: 配置 Flash 模块
6. **定时器初始化**: 配置 ECT 定时器
7. **串口初始化**: 配置 SCI 模块
8. **配置初始化**: 加载和验证配置
9. **中断初始化**: 启用中断系统

## 6. 实时性保证

### 6.1 中断优先级

系统通过合理的中断优先级来保证实时性：

1. **最高优先级**: 发动机位置中断（必须及时响应）
2. **高优先级**: 喷油器控制中断
3. **中优先级**: 通信中断
4. **低优先级**: 实时时钟中断

### 6.2 计算延迟

系统通过以下方式最小化计算延迟：

- 使用双缓冲避免数据竞争
- 在中断中只做必要的工作
- 复杂计算放在主循环中
- 使用原子操作保护关键数据

### 6.3 性能监控

系统跟踪以下性能指标：

- 计算执行时间
- ISR 延迟
- 主循环执行时间
- 通信处理时间

## 7. 错误处理

### 7.1 配置验证

系统在启动时验证配置的有效性：

- 检查传感器范围是否合理
- 验证表格数据是否在有效范围内
- 检查内存地址是否合法

### 7.2 运行时错误

系统通过以下方式处理运行时错误：

- 发送错误代码到通信接口
- 使用默认值替代无效数据
- 记录错误计数器

### 7.3 同步丢失检测

发动机位置解码器会检测同步丢失：

- 监控齿脉冲间隔
- 检测异常脉冲
- 在同步丢失时禁用燃油和点火

## 8. 总结

FreeMS2 是一个设计精良的发动机管理系统，具有以下特点：

1. **模块化设计**: 清晰的模块划分，易于维护和扩展
2. **实时性保证**: 通过中断和双缓冲机制保证实时响应
3. **灵活性**: 支持多种传感器配置和发动机类型
4. **可调参性**: 支持实时调参和数据记录
5. **可靠性**: 完善的错误处理和同步检测机制

系统通过精心设计的架构和实现，为发动机管理提供了稳定可靠的解决方案。
