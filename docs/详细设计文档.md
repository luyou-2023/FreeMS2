# FreeMS2 详细设计文档

## 1. 设计概述

### 1.1 设计目标

FreeMS2 的设计遵循以下原则：

- **实时性**: 确保对发动机事件的及时响应
- **可靠性**: 通过多重验证和错误处理保证系统稳定
- **可维护性**: 清晰的代码结构和模块划分
- **可扩展性**: 易于添加新功能和传感器支持
- **性能**: 优化计算效率，减少延迟

### 1.2 设计约束

根据 `DesignDecisions.txt`，系统有以下设计约束：

- 不支持 MicroSquirt
- 不支持软件峰值保持（P&H）
- 仅支持 MS2Extra 3.1.0 顺序引脚配置（及其子集）
- 不支持 IAC 步进电机控制

```
│ - 业务逻辑                               │
│ - 计算算法                               │
│ - 调度管理                               │
└─────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────┐
│ 服务层 (Service)                        │
│ - 通信服务                               │
│ - 数据管理                               │
│ - 配置管理                               │
└─────────────────────────────────────────┘
           ↓
```

### 2.2 模块划分

#### 2.2.1 核心模块

**main.c** - 主循环模块
- 职责: 系统主循环，调度所有非 ISR 任务
- 接口: 
  - 输入: `coreStatusA` 标志位
  - 输出: 计算后的喷油脉宽和点火参数
- 设计模式: 事件驱动循环

**init.c** - 初始化模块
- 职责: 系统初始化，配置硬件
- 接口: `void init()` - 主初始化函数
- 子模块:
  - `initPLL()`: PLL 初始化
  - `initIO()`: I/O 初始化
  - `initAllPagedRAM()`: 分页 RAM 初始化
  - `initVariables()`: 变量初始化
  - `initFlash()`: Flash 初始化
  - `initECTTimer()`: 定时器初始化
  - `initSCIStuff()`: 串口初始化
  - `initConfiguration()`: 配置初始化
  - `initInterrupts()`: 中断初始化

#### 2.2.2 计算模块

**coreVarsGenerator.c** - 核心变量生成
- 职责: 从 ADC 原始值生成核心物理量
- 输入: `ADCArray` - ADC 原始值数组
- 输出: `CoreVar` - 核心变量结构
- 算法:
  ```c
  void generateCoreVars() {
      // 1. 读取 ADC 值
      // 2. 应用转换表或线性转换
      // 3. 边界检查和默认值处理
      // 4. 存储到 CoreVars
  }
  ```

**derivedVarsGenerator.c** - 派生变量生成
- 职责: 从核心变量计算派生变量
- 输入: `CoreVar` - 核心变量
- 输出: `DerivedVar` - 派生变量
- 计算内容:
  - LoadMain: 负荷值
  - VEMain: 容积效率
  - Lambda: 目标空燃比
  - AirFlow: 空气流量

**fuelAndIgnitionCalcs.c** - 燃油和点火计算
- 职责: 计算最终的喷油脉宽和点火参数
- 输入: `DerivedVar` - 派生变量
- 输出: `injectorMainPulseWidths[]` - 喷油脉宽数组
- 计算流程:
  1. 基础脉宽计算
  2. 应用各种修正
  3. 计算每缸脉宽
  4. 添加死区时间

#### 2.2.3 通信模块

**commsCore.c** - 通信核心
- 职责: 处理通信协议和数据包
- 主要函数:
  - `decodePacketAndRespond()`: 解码数据包并响应
  - `finaliseAndSend()`: 完成数据包并发送
- 协议处理:
  - 数据包解析
  - 校验和验证
  - 错误处理

**commsISRs.c** - 通信中断
- 职责: 串口中断处理
- 功能:
  - 接收字节处理
  - 发送字节处理
  - 数据包组装和解析
  - 转义字符处理

#### 2.2.4 中断处理模块

**interrupts.c** - 中断向量表
- 职责: 定义中断向量和 ISR 入口
- 中断类型:
  - 定时器中断
  - 串口中断
  - 实时时钟中断

**injectionISRs.c** - 喷油器中断
- 职责: 喷油器控制中断处理
- 实现: 通过宏定义生成多个 ISR
- 功能:
  - 喷油器开启
  - 喷油器关闭
  - 分级喷油器控制

**realtimeISRs.c** - 实时中断
- 职责: 实时时钟中断处理
- 功能:
  - 系统时钟更新
  - 超时检测
  - 周期性任务触发

#### 2.2.5 发动机位置解码模块

系统支持多种解码器，每个解码器实现相同的接口：

**decoderInterface.h** - 解码器接口
```c
// 主 RPM 中断
void PrimaryRPMISR(void);

// 次 RPM 中断  
void SecondaryRPMISR(void);
```

**Simple.c** - 简单解码器
- 适用: 基本测试和开发
- 特点: 每转一个脉冲

**MissingTeeth.c** - 缺齿解码器
- 适用: 36-1, 60-2 等缺齿模式
- 特点: 通过缺齿检测同步

**NipponDenso.c** - 日本电装解码器
- 适用: 丰田发动机 (24/2)
- 特点: 半顺序喷油支持

**Subaru-36-2-2-2.c** - 斯巴鲁解码器
- 适用: 斯巴鲁发动机
- 特点: 特殊的 36-2-2-2 模式

**MiataNB.c** - 马自达解码器
- 适用: 马自达 Miata NB
- 特点: 特定的传感器配置

## 3. 数据结构设计

### 3.1 核心数据结构

#### 3.1.1 CoreVar - 核心变量

```c
typedef struct {
    unsigned short IAT;      // 进气温度 (K * 100)
    unsigned short CHT;      // 缸盖温度 (K * 100)
    unsigned short TPS;      // 节气门位置 (0-64000 = 0-100%)
    unsigned short EGO;      // 氧传感器 (Lambda * 32768)
    unsigned short BRV;      // 电池电压 (mV)
    unsigned short MAP;      // 歧管压力 (kPa * 100)
    unsigned short AAP;      // 大气压力 (kPa * 100)
    unsigned short MAT;      // 歧管温度 (K * 100)
    unsigned short EGO2;     // 第二氧传感器
    unsigned short IAP;      // 中冷器压力
    unsigned short MAF;      // 质量空气流量
    unsigned short RPM;      // 发动机转速
    unsigned short DRPM;    // 转速变化率
    unsigned short DDRPM;   // 转速变化加速度
} CoreVar;
```

**设计考虑**:
- 使用定点数避免浮点运算
- 单位统一便于计算
- 预留扩展字段

#### 3.1.2 DerivedVar - 派生变量

```c
typedef struct {
    unsigned short LoadMain;        // 主负荷
    unsigned short VEMain;          // 容积效率 (512 = 100%)
    unsigned short Lambda;          // 目标空燃比 (32768 = 1.0)
    unsigned short AirFlow;         // 空气流量
    unsigned short densityAndFuel;  // 密度和燃油因子
    unsigned short BasePW;          // 基础喷油脉宽
    unsigned short ETE;             // 发动机温度修正
    signed short TFCTotal;          // 瞬态燃油修正
    unsigned short EffectivePW;     // 有效喷油脉宽
    unsigned short IDT;             // 喷油器死区时间
    unsigned short RefPW;           // 参考喷油脉宽
} DerivedVar;
```

**设计考虑**:
- 分离核心变量和派生变量便于调试
- 使用有符号数支持负修正
- 保留中间计算结果

#### 3.1.3 ADCArray - ADC 数组

```c
typedef struct {
    unsigned short MAP;
    unsigned short IAT;
    unsigned short CHT;
    unsigned short TPS;
    unsigned short EGO;
    unsigned short BRV;
    unsigned short AAP;
    unsigned short MAT;
    unsigned short EGO2;
    unsigned short IAP;
    unsigned short MAF;
```

**设计考虑**:
- 结构体便于按名称访问
- 双缓冲避免数据竞争

## 5. 算法设计

### 5.1 燃油计算算法

#### 5.1.1 基础脉宽计算

```
BasePW = (FuelConstant * AirFlow) / densityAndFuel

其中:
FuelConstant = (masterFuelConstant / injectorFlow) * perCylinderVolume / stoichiometricAFR
AirFlow = MAP * VE / 100% (速度密度模式)
densityAndFuel = (IAT * Lambda / stoichiometricLambda) * fuelDensity / divisor
```

#### 5.1.2 修正应用

```
EffectivePW = BasePW * (1 + ETE/100) + TFC
FinalPW = EffectivePW + IDT + PCFC
```

#### 5.1.3 每缸修正

```
ChannelPW = FinalPW * (1 + PerCylinderTrim[channel]/100)
```

### 5.2 转速计算算法

#### 5.2.1 简单模式

```
RPM = ticksPerMinute / timeBetweenPulses

其中:
ticksPerMinute = 60 * (1000000 / tickPeriod)
timeBetweenPulses = currentTimestamp - lastTimestamp
```

#### 5.2.2 缺齿模式

```
1. 检测缺齿（脉冲间隔异常大）
2. 同步到缺齿位置
3. 计算每个齿的间隔
4. 根据齿数计算 RPM
```

### 5.3 表格查找算法

#### 5.3.1 线性插值

```c
unsigned short interpolate(
    unsigned short x1, unsigned short y1,
    unsigned short x2, unsigned short y2,
    unsigned short x
) {
    if (x2 == x1) return y1;
    return y1 + ((long)(y2 - y1) * (x - x1)) / (x2 - x1);
}
```

#### 5.3.2 二维表格查找

```c
1. 在 RPM 轴上找到 x1, x2
2. 在 Load 轴上找到 y1, y2
3. 在 x1 行进行 Load 插值得到 z1
4. 在 x2 行进行 Load 插值得到 z2
5. 在 RPM 方向插值得到最终值
```

## 6. 内存管理设计

### 6.1 内存布局

```
Flash 区域:
- 0x3E4000: 固定配置 1
- 0x3E4000: 固定配置 2
- 0x3EC000: 代码段
- 0x388000: 分页 Flash 页面 38
- 0x398000: 分页 Flash 页面 39
- 0x3A8000: 分页 Flash 页面 3A
- ...

RAM 区域:
- 0x1000-0x3FFF: 运行时数据
- 分页 RAM: 表格数据（从 Flash 复制）
```

### 6.2 分页内存管理

系统使用分页内存来扩展可用空间：

- **PPAGE**: Flash 页面寄存器
- **RPAGE**: RAM 页面寄存器

访问分页内存时：
1. 保存当前页面
2. 设置目标页面
3. 访问数据
4. 恢复原页面

### 6.3 双缓冲管理


## 7. 通信协议设计

### 7.1 数据包格式

```
[START] [FLAGS] [PAYLOAD_ID] [LENGTH] [SEQUENCE] [DATA...] [CHECKSUM] [STOP]
```

- **START**: 0x7E (固定值)
- **FLAGS**: 
  - BIT0: 有长度字段
  - BIT1: 有序列号
  - BIT2: 是 NACK
  - ...
- **PAYLOAD_ID**: 16 位，请求 ID，响应 ID = 请求 ID + 1
- **LENGTH**: 16 位，数据长度（如果 FLAGS 指示）
- **SEQUENCE**: 8 位，序列号（如果 FLAGS 指示）
- **DATA**: 可变长度
- **CHECKSUM**: 8 位，所有字节的累加和
- **STOP**: 0x7E (固定值)

### 7.2 转义机制

特殊字节需要转义：
- 0x7E (START/STOP) → 0x7D 0x5E
- 0x7D (ESC) → 0x7D 0x5D

### 7.3 错误处理

- **payloadTooShortForSpecifiedFields**: 数据包太短
- **payloadLengthHeaderMismatch**: 长度不匹配
- **invalidPayloadID**: 无效的负载 ID
- **unrecognisedPayloadID**: 未识别的负载 ID

## 9. 性能优化设计

### 9.1 计算优化

- 使用定点数避免浮点运算
- 预计算常量（如 `bootFuelConst`）
- 使用查找表替代复杂计算
- 优化常用路径（最常见配置优先检查）

### 9.2 内存优化

- 使用分页内存扩展空间
- 双缓冲最小化内存使用
- 函数分段（`-ffunction-sections`）支持垃圾回收

### 9.3 实时性优化

- 中断中只做必要工作
- 复杂计算放在主循环
- 使用原子操作保护关键数据
- 最小化中断禁用时间

## 12. 总结

FreeMS2 的详细设计体现了以下特点：

1. **清晰的模块划分**: 每个模块职责明确
2. **良好的接口设计**: 模块间耦合度低
3. **灵活的数据结构**: 易于扩展和修改
4. **完善的错误处理**: 保证系统可靠性
5. **性能优化**: 兼顾实时性和计算效率
6. **可扩展性**: 易于添加新功能

这些设计决策确保了系统的可维护性、可靠性和可扩展性。
